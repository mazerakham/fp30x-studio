The crash was the smaller half

silent since the refactor

The refactor that moved hammer_strike_point into the preset moved three other things with it. cmd_partials kept reading module defaults for all four. Only the strike point raised AttributeError; the other three were optional arguments, so they went quiet.

  • hammer_strike_point — used 0.091, preset says 0.1185. The visible crash.
  • rolloff_per_octave — ignored. This is the one that mattered.
  • inharmonicity_decades_per_octave, inharmonicity_floor — ignored.
  • decay_halving_semitones — ignored; tau_1 used the library default.

Consequence: rolloff_at is the largest per-register correction in the model, so with it ignored the printed an column was identical for every note and every preset, up to frequency. acoustic and b2-darkbass differ in nothing but rolloff_per_octave — they printed the same bass spectrum.

How the amplitudes were checked against the renderer

Rendering each note through render_string with the pedal held and no damping, then reading partial peaks off a 2 s Hann-windowed FFT starting 250 ms after the strike. For each partial a single-sine reference was built from the printed an and pushed through the identical window and transform, so the analysis bias (Hann weighting of a decaying sinusoid) cancels rather than being modelled. A ratio of 1.000 means the printed number is the number in the audio.

unison_depth and hammer_noise were zeroed for the measurement only — an does not depend on either, and both would smear the peak. Confirmed by a test that computes an by the renderer's own route on five presets and five notes.

Fixed: `synth partials` crashed, and had been printing the wrong spectrum before it crashed.

**Artifact:** commit `875b4aa` on `fpx-format-spec`, ~/workspace/audio/fp30x-studio
Files: `fp30x_studio/synth/cli.py`, `fp30x_studio/synth/model.py`, `tests/test_synth.py`

**What was wrong.** The refactor that moved `hammer_strike_point` into the preset moved three
other things with it. `cmd_partials` kept reading module-level defaults for all four. Only the
strike point crashed (AttributeError); the other three were optional arguments, so they failed
silently:

| read from the module | should come from the preset |
|---|---|
| `HAMMER_STRIKE_POINT` (0.091) | `hammer_strike_point` (0.1185) |
| rolloff, flat | `rolloff_per_octave` |
| B defaults | `inharmonicity_decades_per_octave`, `inharmonicity_floor` |
| halving 15.5 | `decay_halving_semitones` |

`rolloff_at` is the largest per-register correction in the model, so ignoring
`rolloff_per_octave` meant the printed `a_n` column was **identical for every note and every
preset**, up to frequency. On note 28 it printed rolloff 3.018 where the renderer uses 0.821
(acoustic) / 1.993 (b2-darkbass), and a fundamental of 0.577 where the true value is 0.043 —
a 13.6x error, in the direction that hides the bass clank.

**Verification (the 8 runs requested).** Each note rendered through `render_string`, partial
peaks read off an FFT, compared against the printed `a_n` pushed through the identical
window/transform so the analysis bias cancels:

|---|---|---|---|
| acoustic | 28 | 32 | 0.55% |
| acoustic | 33 | 32 | 0.56% |
| acoustic | 45 | 32 | 0.49% |
| acoustic | 69 | 18 | 0.64% |
| b2-darkbass | 28 | 32 | 0.84% |
| b2-darkbass | 33 | 32 | 0.77% |
| b2-darkbass | 45 | 30 | 1.17% |
| b2-darkbass | 69 | 18 | 0.64% |

Partials below -60 dB deviate more (up to 4%): those are the strike-point comb nulls at
n = 8.44k, 72-82 dB down, where spectral leakage from their neighbours sets the measurement
